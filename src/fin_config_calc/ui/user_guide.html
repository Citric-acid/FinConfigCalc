通用管报ETL工具用户操作手册

系统定位面向管报场景的本地数据处理工具。通过 Excel 参数表灵活编排清洗、转换、映射、校验、对账与分摊任务，无需修改程序即可组合处理流程；所有任务均在本机执行，无需联网，业务数据不离开本地环境。

参数化配置 处理流程灵活组合 Excel / Parquet 本地离线执行
01 / 开始使用

界面与快速开始

主界面负责选择调度表、预览执行步骤、运行任务并收集日志。调度表中的每一行代表一个可独立执行的 Service 功能。

1选择调度表输入 .xlsx 或 .xlsm 文件路径。
2填写工作表默认为“调度”，可改为实际工作表名。
3先预览点击“预览任务步骤”，检查顺序和说明。
4再执行点击“执行调度”，观察进度与任务信息。
界面元素作用使用建议
调度表路径指定包含调度配置的 Excel 文件使用完整路径，避免移动文件后路径失效
调度表名称指定 Excel 工作表不填写时使用“调度”
预览任务步骤校验配置并列出 enabled=Y 的任务，不执行数据处理修改调度表后先预览
执行调度按 order 依次运行任务执行期间按钮会暂时禁用
复制日志复制当前任务信息的纯文本报错时将日志一并反馈
使用说明在系统默认浏览器打开本手册页面可使用浏览器打印或另存 PDF
推荐操作顺序保存并关闭正在编辑的输入/输出 Excel 文件，先预览，再执行。任务成功后检查 DONE 行和输出文件。
02 / 调度核心

调度表配置

读取 Excel指定工作表
校验配置字段、顺序、JSON
筛选并排序enabled=Y / order 升序
逐步执行失败即中止
列名必填填写规则示例
order是唯一数值；决定执行顺序，可不连续10、20
function是Service 函数路径service.unpivot
params是JSON 对象字符串；无参数可填 {} 或留空{"input_file_path":"D:/data.xlsx",...}
enabled是仅允许 Y、N 或空；不区分大小写Y
comments否任务说明，在预览和 START 日志中显示将月度宽表转成长表

完整调度行示例

order:    10
function: service.filter_by_conditions
params:   {"input_file_path":"D:/finance/detail.xlsx","input_sheet_name":"明细","conditions":{"period":"202601","amount":{"ge":100}},"output_file_path":"D:/finance/output/filtered.parquet"}
enabled:  Y
comments: 筛选 2026 年 1 月且金额不小于 100 的记录
任务失败后的行为任务按顺序串行执行。任何一步抛出错误时，本次调度立即中止，后面的步骤不会继续，也不会自动回滚此前已生成的文件。
03 / 通用约定

文件、路径与 JSON 规则

Excel 输入

支持 .xlsx、.xlsm。存在多个工作表时，请填写对应的 *_sheet_name。

Parquet 输入

文件后缀为 .parquet，不要填写工作表参数。

输出目录

多数 Service 会自动创建输出文件的父目录。输出格式由扩展名决定。

Windows 路径

JSON 中建议使用正斜杠：D:/finance/data.xlsx，避免反斜杠转义。

JSON 类型写法

{
  "text": "ACT",
  "number": 100.5,
  "enabled": true,
  "empty": null,
  "columns": ["period", "entity", "amount"],
  "mapping": {"source": "budget", "version": 2}
}
Excel 文件占用输出为 Excel 时，请先关闭同名文件。文件被 Excel 占用通常会导致写入权限错误。
Service 01

allocation：按因子分摊

使用分摊因子把待摊金额从“分出维度”分配到“分入维度”，并通过维度元数据将汇总成员展开到基础成员。

待摊数据金额 + 业务维度
筛选并展开因子out_* / in_* / rate
匹配 × 权重金额 × rate
分摊结果可聚合、可补固定列
service.allocation(
  input_file_path, factor_file_path, metadata_file_path, output_file_path,
  value_columns, input_sheet_name=None, factor_sheet_name=None,
  metadata_sheet_name=None, rate_column="rate", out_prefix="out_",
  in_prefix="in_", keep_label=False, group_by=None,
  group_by_exclude=None, abs_delta=5, factor_output_file_path=None,
  factor_query=None, assign_result=None
)
核心参数说明
value_columns需要分摊的数值列，可填字符串或字符串列表。
factor_file_path因子表。至少包含一个 out_*、一个 in_* 和权重列。
metadata_file_path维度元数据，默认字段为 dimension、element_code、is_base、parent。
factor_query执行前筛选因子，例如按版本或场景选择本次规则。
factor_output_file_path可选；保存筛选且展开后的因子，便于审计。
group_by / group_by_exclude控制最终聚合维度；二者通常只选一个。
assign_result为结果增加或覆盖固定列，例如数据来源、版本。

因子表示意

out_cost_centerin_productratescenario
CC100P010.6ACT
CC100P020.4ACT
{
  "input_file_path": "D:/data/cost.xlsx",
  "factor_file_path": "D:/config/factor.xlsx",
  "metadata_file_path": "D:/config/metadata.xlsx",
  "output_file_path": "D:/output/allocated.parquet",
  "value_columns": ["amount"],
  "factor_query": {"scenario": "ACT"},
  "assign_result": {"source": "allocation", "version": 1}
}
重点检查同一分出组合内，每个 in_* 字段必须全空或全非空；规则必须至少指定一个分入维度。因子权重列名不叫 rate 时需设置 rate_column。
Service 02

assign_columns：添加或覆盖固定列

为输入数据的每一行设置相同的字段值。适合补充场景、版本、来源系统、批次等审计字段；同名列已存在时会被覆盖。

service.assign_columns(input_file_path, column_values, output_file_path, input_sheet_name=None)
{
  "input_file_path": "D:/data/detail.xlsx",
  "input_sheet_name": "明细",
  "column_values": {"scenario": "BUDGET", "version": 2, "reviewed": false},
  "output_file_path": "D:/output/detail_tagged.parquet"
}
处理前account | amount
6001 | 120
→
处理后account | amount | scenario | version
6001 | 120 | BUDGET | 2
Service 03

check_metadata：维度成员合法性检查

先检查元数据自身是否合法，再检查业务数据中的维度成员是否存在于元数据中。错误明细写入指定文件。

service.check_metadata(input_file_path, metadata_file_path, output_file_path,
                       input_sheet_name=None, metadata_sheet_name=None)
{
  "input_file_path": "D:/data/ledger.parquet",
  "metadata_file_path": "D:/config/metadata.xlsx",
  "metadata_sheet_name": "维度元数据",
  "output_file_path": "D:/output/metadata_errors.xlsx"
}
这是一个“门禁”任务元数据自身有误时不会生成业务数据检查结果；业务数据存在非法成员时，会先写出错误明细，再抛出错误并中止后续调度。输出文件非空意味着检查未通过。
Service 04

concat：多个文件纵向拼接

依次读取多个 Excel 或 Parquet 文件并纵向追加。字段不一致时按字段并集对齐，缺少的字段填空值；可为每个来源增加标识。

service.concat(input_file_paths, output_file_path, input_sheet_names=None,
               source_column=None, source_values=None)
{
  "input_file_paths": ["D:/data/jan.xlsx", "D:/data/feb.xlsx"],
  "input_sheet_names": ["明细", "明细"],
  "source_column": "source_month",
  "source_values": ["202601", "202602"],
  "output_file_path": "D:/output/q1.parquet"
}
列表长度必须一致input_sheet_names、source_values 一旦提供，其元素数量必须与 input_file_paths 相同。source_column 和 source_values 必须同时提供或同时省略。
Service 05

append_with_overwrite：覆盖分区并追加

从存量文件删除符合条件的旧分区，再把上传文件追加到末尾。存量文件本身就是输出文件，会被原位更新。

存量文件保留其他分区
删除目标分区overwrite_conditions
校验上传数据每行必须满足条件
追加并原位写回
service.append_with_overwrite(database_file_path, upload_file_path,
                              overwrite_conditions, database_sheet_name=None,
                              upload_sheet_name=None)
{
  "database_file_path": "D:/database/history.parquet",
  "upload_file_path": "D:/upload/actual_202601.xlsx",
  "upload_sheet_name": "明细",
  "overwrite_conditions": {"period": "202601", "scenario": "ACT"}
}
原位更新，执行前请备份overwrite_conditions 不能为空，上传文件也不能为空。只要上传文件中有一行不满足覆盖条件，函数就会拒绝写入。
Service 06

diff_by_row：输出行级差异

比较两个数据集，输出只在一侧出现或内容不同的行，并用来源列区分两侧记录。

service.diff_by_row(first_file_path, second_file_path, output_file_path,
                    check_columns=None, exclude_columns=None, column_map=None,
                    first_sheet_name=None, second_sheet_name=None,
                    diff_source_col="_tmp_diff_src")
参数用途
check_columns只比较指定列。
exclude_columns比较时排除指定列，例如加载时间。
column_map两表列名不一致时进行映射。
diff_source_col输出中标记差异行来自哪一侧的临时字段名。
{
  "first_file_path": "D:/data/expected.parquet",
  "second_file_path": "D:/data/actual.parquet",
  "check_columns": ["account", "entity", "amount"],
  "exclude_columns": ["load_time"],
  "output_file_path": "D:/output/row_diff.parquet"
}
Service 07

diff_by_row_to_excel：生成增删改差异报表

先执行行级比较，再按关联键归并新旧记录，生成便于人工检查的 Excel 差异明细。实际文件名会附加增、删、改数量。

service.diff_by_row_to_excel(first_file_path, second_file_path, output_file_path,
                             join_keys, check_columns=None, exclude_columns=None,
                             column_map=None, output_sheet_name="差异明细")
{
  "first_file_path": "D:/data/old.xlsx",
  "first_sheet_name": "明细",
  "second_file_path": "D:/data/new.xlsx",
  "second_sheet_name": "明细",
  "join_keys": ["voucher_id", "line_id"],
  "check_columns": ["account", "amount", "description"],
  "output_file_path": "D:/output/difference.xlsx"
}
选择关联键join_keys 应能稳定识别同一条业务记录。键不唯一或会变化时，增删改统计可能不符合预期。
Service 08

diff_by_group：分组汇总差异

分别按维度汇总左右两表，再比较求和结果。适合总账与明细、系统 A 与系统 B 的金额对账。

service.diff_by_group(left_file_path, left_groupby, left_sum,
                      right_file_path, output_file_path, right_groupby=None,
                      right_sum=None, keep_groupby="left", abs_delta=0.5)
{
  "left_file_path": "D:/data/system_a.parquet",
  "left_groupby": ["period", "entity", "account"],
  "left_sum": ["amount"],
  "right_file_path": "D:/data/system_b.parquet",
  "right_groupby": ["month", "company", "account_code"],
  "right_sum": ["local_amount"],
  "keep_groupby": "left",
  "abs_delta": 0.5,
  "output_file_path": "D:/output/reconciliation.xlsx"
}
字段按位置对应左右两侧的分组字段列表、求和字段列表应分别等长，并按相同业务含义排列。绝对差异不超过 abs_delta 时视为可忽略。
Service 09

filter_by_conditions：条件筛选

多个字段条件按 AND 组合，只保留全部满足的记录。标量写法等价于 eq。

service.filter_by_conditions(input_file_path, conditions, output_file_path,
                             input_sheet_name=None)
操作符含义示例
eq / ne等于 / 不等于{"scenario":{"ne":"BUDGET"}}
gt / ge / lt / le数值或日期大小比较{"amount":{"ge":100}}
in / not_in属于 / 不属于列表{"region":{"in":["华东","华南"]}}
contains字符串包含{"description":{"contains":"调整"}}
starts_with / ends_with字符串前缀 / 后缀{"account":{"starts_with":"6"}}
is_null / is_not_null空值 / 非空值{"project":{"is_null":true}}
{
  "input_file_path": "D:/data/detail.xlsx",
  "conditions": {
    "period": "202601",
    "region": {"in": ["华东", "华南"]},
    "amount": {"ge": 100},
    "description": {"contains": "调整"}
  },
  "output_file_path": "D:/output/filtered.parquet"
}
Service 10

filter_group_sum_to_excel：筛选、汇总并导出报表

把条件筛选、分组求和和 Excel 报表导出合成一个步骤。可使用字段对照表在英文列名下增加中文说明行。

读取明细
条件筛选可省略
分组求和可省略
Excel 报表可带中文说明
service.filter_group_sum_to_excel(input_file_path, output_file_path,
  field_mapping_file_path=None, field_mapping_sheet_name=None,
  conditions=None, group_sum_params=None, input_sheet_name=None,
  output_sheet_name="Sheet1")
{
  "input_file_path": "D:/data/detail.parquet",
  "conditions": {"scenario": "ACT", "amount": {"ne": 0}},
  "group_sum_params": {
    "group_by": ["period", "entity", "account"],
    "sum_by": ["amount"],
    "abs_delta": 0.01
  },
  "field_mapping_file_path": "D:/config/fields.xlsx",
  "field_mapping_sheet_name": "字段说明",
  "output_file_path": "D:/output/report.xlsx",
  "output_sheet_name": "汇总"
}
字段说明表必须包含 standard 和 comments 两列。配置后，输出第一行为英文列名，第二行为中文说明，第三行开始是数据。
Service 11

mapping_1t：配置驱动的单表映射

读取映射规则，对输入表执行条件匹配、目标字段赋值和行保留控制。适用于科目归类、组织映射、产品线转换等规则较多的场景。

service.mapping_1t(input_file_path, config_file_path, output_file_path,
                   input_sheet_name=None, config_sheet_name=None)
规则字段作用
order_execution映射轮次；控制规则组执行先后。
priority同一轮次内的规则优先级。
mapping_code规则唯一标识。
keep_row控制命中规则后的记录是否保留。
source_field_1 / source_code_1第一个来源字段及匹配值；可按规则表支持更多序号。
output_field_1 / output_code_1第一个输出字段及赋值；可按规则表支持更多序号。
{
  "input_file_path": "D:/data/raw.xlsx",
  "input_sheet_name": "明细",
  "config_file_path": "D:/config/mapping.xlsx",
  "config_sheet_name": "映射规则",
  "output_file_path": "D:/output/mapped.parquet"
}
规则优先级很重要映射结果与规则表内容密切相关。先使用少量样本验证命中顺序、保留行规则和输出字段，再用于完整数据。
Service 12

merge_dims_attribute：补充维度属性

按业务数据中的成员编码关联维度元数据，将成员名称、上级编码等属性补充为新列。可一次配置多个业务维度。

service.merge_dims_attribute(input_file_path, metadata_file_path, relations,
                             output_file_path, input_sheet_name=None,
                             metadata_sheet_name=None)
{
  "input_file_path": "D:/data/ledger.parquet",
  "metadata_file_path": "D:/config/metadata.xlsx",
  "metadata_sheet_name": "维度元数据",
  "relations": {
    "account": {
      "dimension": "d_account",
      "attributes": {
        "element_name": "account_name",
        "parent": "account_parent"
      }
    },
    "entity": {
      "dimension": "d_entity",
      "attributes": {"element_name": "entity_name"}
    }
  },
  "output_file_path": "D:/output/ledger_enriched.parquet"
}
relations 的阅读方法最外层键是输入表字段；dimension 是元数据中要筛选的维度值；attributes 的键是元数据属性列，值是输出的新列名。
Service 13

standardize_columns：统一字段名和类型

根据规则表选择并重命名输入字段、补齐缺失的标准字段、调整列顺序，并按可选的 dtype 转换类型。

service.standardize_columns(input_file_path, config_file_path, field_name,
                            output_file_path, input_sheet_name=None,
                            config_sheet_name=None)

规则表示意

source_fieldstandarddtype
公司编码entitystring
本币金额amountfloat
期间periodstring
（空）scenariostring
{
  "input_file_path": "D:/data/raw.xlsx",
  "config_file_path": "D:/config/columns.xlsx",
  "config_sheet_name": "字段规则",
  "field_name": "source_field",
  "output_file_path": "D:/output/standardized.parquet"
}
类型取值限制dtype 目前只支持 float 和 string。无法转为 float 的非空值会报错；规则中的 standard 不得重复。规则未映射的输入列不会进入结果。
Service 14

unpivot：宽表转长表

将多列指标折叠成“变量列 + 值列”。最常见场景是把一月、二月、三月等月份列转换成多行。

service.unpivot(input_file_path, unpivot_columns, variable_column,
                value_column, output_file_path, input_sheet_name=None)
宽表account | 一月 | 二月
6001 | 100 | 120
→
长表account | month | amount
6001 | 一月 | 100
6001 | 二月 | 120
{
  "input_file_path": "D:/data/monthly.xlsx",
  "input_sheet_name": "月度数据",
  "unpivot_columns": ["一月", "二月", "三月"],
  "variable_column": "month",
  "value_column": "amount",
  "output_file_path": "D:/output/monthly_long.parquet"
}
列名必须准确unpivot_columns 中任一列不存在都会导致任务失败；没有列入该列表的字段作为标识列保留在每一条结果中。
04 / 运行维护

状态与日志说明

类型含义处理方式
START某一步已开始，显示序号、函数和 comments等待对应的 DONE 或错误
DONE某一步成功完成，显示耗时和返回的输出路径检查输出文件是否符合预期
INFO处理统计或普通说明用于了解输入输出行数等信息
WARNING数据可继续处理，但存在需要关注的情况检查来源位置和消息内容
ERROR任务执行失败查看错误位置、错误代码和完整调用栈

状态栏显示当前步骤；进度条按已完成任务数更新。“复制日志”会复制当前界面的所有纯文本日志。

05 / 排错

常见问题

现象常见原因处理建议
找不到文件路径拼写错误、相对路径基准不明确、文件已移动改用完整路径，并在资源管理器确认文件存在
找不到工作表*_sheet_name 与 Excel 标签名称不一致检查空格、大小写和隐藏工作表
params 解析失败JSON 使用单引号、末尾多逗号、反斜杠未转义使用双引号；Windows 路径改用 /
缺少必填列调度表或业务配置表字段名不准确对照本手册参数表检查列头
PermissionError输出 Excel 正被打开，或目录无写入权限关闭文件；选择有权限的输出目录
任务停在某一步大文件处理耗时、网络盘速度慢观察日志和磁盘活动；先用少量数据验证配置
