# FinConfigCalc 项目现状与后续计划

本文档以当前仓库实现为准，区分已经存在的行为和可选后续工作，不将未实现的架构方案描述成既定能力。

## 当前项目

FinConfigCalc 是一个面向本地财务数据加工的 Python 工具。用户通过 Excel 调度表配置步骤及 JSON 参数，程序按顺序调用 `fin_config_calc.service` 中的处理函数。项目使用 Python 3.12、Polars 和 `src` 布局。

当前代码依赖方向为：

```text
ui -> service -> utils
```

- `ui/textual_app.py`：Textual 终端界面，负责读取调度表、预览步骤、后台执行、进度及日志展示。
- `service/`：按业务操作划分的服务函数，例如分配、字段检查、拼接、差异比较、过滤汇总、映射、标准化和逆透视。
- `utils/`：Polars 数据处理、调度器及文件读写实现。
- `tests/unit`、`tests/integration`：工具、服务和界面测试。

## 调度表与运行行为

调度表默认工作表为“调度”，必须包含以下列：

| 列 | 约定 |
| --- | --- |
| `order` | 唯一数值，用于确定执行顺序 |
| `function` | `fin_config_calc` 包内处理函数的模块路径；调度步骤应使用 `service` 中的函数 |
| `params` | 字典、空值或 JSON 对象字符串，按关键字参数传给函数 |
| `enabled` | `Y` 执行；`N` 或空值跳过 |
| `comments` | 可选的步骤说明 |

调度器会在执行前检查必填列、序号唯一性、启用标记、函数名和参数 JSON；预览只列出启用步骤。任务按 `order` 升序串行执行，步骤抛出异常会终止后续步骤。界面在 Textual worker 中执行任务，并展示步骤耗时和日志。程序不会自动删除之前步骤已经写出的文件。

## 数据格式与依赖

- Polars 是数据处理的 DataFrame 实现；当前代码不使用 Pandas DataFrame。
- openpyxl 用于 Excel 读取和写出，包括差异报表；Parquet 由 Polars 读写。
- Textual 提供终端界面，Rich 用于界面中的富文本日志展示。
- Arrow 被多条件映射表达式上下文以 `arrow` 名称显式暴露，属于现有调度配置的兼容接口。
- Loguru 提供处理日志；PyInstaller 是可选的打包依赖；pytest、Ruff、Pyright 是开发依赖。

这些包承担不同职责，不因其中一个包间接依赖另一个就移除源码直接使用的依赖。依赖替换前应检查现存调度表和映射表达式兼容性。

输入支持 `.xlsx`、`.xlsm` 和 `.parquet`；输出支持 `.xlsx` 和 `.parquet`。Excel 写出使用 openpyxl 的只写工作簿分批写入。金额/汇总列中，null 和空字符串按零处理；非法非空值及 NaN、正负无穷会报错，不静默归零。分摊权重列仍按分摊实现当前的过滤规则处理。

## 当前限制

- 调度为单机、线性、串行执行，没有 DAG、多任务并发或集中式任务平台。
- 没有统一的运行审计目录、结构化运行清单或自动回滚；失败时此前已生成的文件仍保留。
- 函数路径在执行时动态解析，参数按函数关键字参数传递；尚无逐步骤参数模型和完整的静态预检。
- 没有内置参数审批、权限控制或多人协作版本管理。

## 后续工作候选

以下是可根据实际需求安排的增强项，不代表当前已经实现：

1. 为服务函数建立注册表和逐步骤参数校验，让预览阶段能够发现无效函数路径及参数错误。
2. 为每次运行记录步骤状态、耗时、输入输出行数、配置摘要和错误摘要，便于复核失败任务。
3. 评估输出文件原子替换或备份策略，降低任务失败后误用旧文件或部分产物的风险。
4. 增加架构测试，校验 `ui -> service -> utils` 的依赖方向，并在 CI 中运行测试、Ruff 和 Pyright。

实现这些增强前，应保持调度表现有列、JSON 参数和已发布映射表达式的兼容性，除非明确计划迁移。

## 开发验证

在 Windows 上使用项目环境执行：

```powershell
.\.venv\python.exe -m pytest
.\.venv\python.exe -m ruff check .
.\.venv\python.exe -m ruff format --check .
.\.venv\python.exe -m pyright
```
