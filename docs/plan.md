# 参数驱动财务加工项目计划

建立一个 Python 3.12 + Polars 的 `src` 布局项目。第 2 层命名为 `service`，负责把 Excel 参数工作簿解析为经过校验的声明式规则，并按顺序执行读取、清洗、映射、转换、分摊和输出；`utils` 只保留无业务含义的通用底层工具。`ui` 暂时只保留空目录和包标识，未来再接入 Tkinter 或其他桌面框架。

## 阶段一：工程与边界

1. 初始化 Python 包工程与开发工具：Python 3.12、`pyproject.toml`、`src/fin_config_calc` 包、pytest、Ruff、Pyright；声明 Polars、openpyxl、XlsxWriter、Pydantic 等依赖，并提供统一的测试、检查和运行入口。
2. 建立三层目录和单向依赖约束：`ui -> service -> utils`。在 README 和包导出中明确 `utils` 只能放纯函数/通用 I/O 辅助，所有财务语义、规则和处理步骤都归 `service`；禁止 `service` 反向导入 `ui`。
3. 定义 `service` 的公共应用接口和核心数据契约：任务请求、执行上下文、步骤结果、校验问题、运行摘要、产物清单；未来 UI 只依赖 `ProcessingService.validate/run` 门面，不直接操作 Polars 或 Excel 解析器。依赖步骤 1-2。

## 阶段二：Excel 参数模型

4. 定义单工作簿多 Sheet 的首版模板及版本字段，建议固定 Sheet：`任务`、`数据源`、`字段`、`清洗`、`映射`、`分摊`、`输出`；每行使用稳定 ID、启用标记和执行顺序，列名、类型、必填性、默认值及跨 Sheet 引用均形成明确 Schema。依赖步骤 3。
5. 实现参数工作簿加载与结构化解析边界：openpyxl 只负责工作簿结构/单元格读取，解析结果进入 Pydantic 规则模型；禁止运行 Excel 宏、任意 Python 表达式或动态 `eval`，规则仅使用白名单操作符。依赖步骤 4。
6. 实现执行前规则校验：Sheet/列完整性、ID 唯一性、步骤顺序、源/字段引用、类型兼容、映射重复或缺失、分摊权重字段与输出路径检查；输出包含严重级别、Sheet、行号、规则 ID 和可读消息的校验报告。依赖步骤 5。
7. 编写带注释和示例数据的参数模板，并让模板生成/读取测试与 Schema 同源，避免文档与代码漂移。可与步骤 6 并行，依赖步骤 4-5。

## 阶段三：处理服务

8. 在 `service` 内建立步骤协议与注册表：每个步骤接受执行上下文和 Polars DataFrame/LazyFrame，返回数据及指标；执行器按参数表顺序运行白名单步骤，统一处理取消、异常、进度和产物记录。依赖步骤 3、6。
9. 实现 Excel 数据源与输出适配器：首期仅支持 `.xlsx`，完成工作表/表头/范围选择、显式类型转换、空值策略、目标目录和文件命名；业务数据尽早转为 Polars，Excel 库不渗透到处理步骤。可与步骤 8 并行，依赖步骤 3。
10. 实现清洗、映射和通用转换步骤：去空、去重、文本规范化、类型转换、条件过滤、字段重命名/派生、字典映射、连接和聚合；每种规则均有确定的输入 Schema、白名单操作符、错误策略和行数指标。依赖步骤 8-9。
11. 实现分摊步骤：按配置确定待分摊金额、接收维度、权重来源、分组键和舍入规则；处理零权重、缺失权重、尾差归集和负数，并生成分摊前金额、分摊后金额、差异及异常明细。依赖步骤 8-10。
12. 实现 `ProcessingService` 端到端门面：先校验参数，再读取源数据，执行有序步骤，导出结果；失败时停止后续写入并返回结构化错误，成功时返回输出文件、快照、平衡报告和运行摘要。依赖步骤 6、8-11。

## 阶段四：审计与运行入口

13. 建立每次运行独立的审计目录，保存结构化日志、规则校验报告、步骤耗时/输入输出行数、可选中间快照、分摊平衡报告和最终产物索引；对参数文件记录路径、修改时间和内容摘要。依赖步骤 8、12。
14. `ui` 目录只创建空包占位，不定义控制器、视图模型或具体 GUI 依赖；未来选择 Tkinter、PySide6 或其他框架时，统一调用 `ProcessingService`。依赖步骤 1-3。
15. 提供一个最小命令行适配器作为当前可执行验收入口，调用 `ProcessingService` 的 `validate` 和 `run`，用于在 GUI 开发前验证核心能力。依赖步骤 12-13。
16. 补充架构、参数模板说明、目录职责、扩展新步骤的方法、错误与审计产物说明，以及本地开发/运行命令。依赖前述实现，可在各阶段同步更新。

## 阶段五：测试与验收

17. 建立分层测试夹具：最小参数工作簿、有效/无效规则、原始业务数据、映射字典、含尾差和零权重的分摊样本；测试数据不包含真实财务信息。可从步骤 4 起并行维护。
18. 单元测试覆盖规则解析/校验、每类步骤、分摊守恒与舍入、路径和错误策略；集成测试覆盖从参数工作簿与源 Excel 到结果、快照、日志和平衡报告的完整运行。依赖对应实现。
19. 增加依赖方向测试或静态规则，确保 `utils` 不依赖 `service/ui`、`service` 不依赖 `ui`，并执行完整质量门禁。依赖步骤 1-16。

## 相关文件

- `pyproject.toml`：Python 版本、依赖、命令入口、Ruff/Pyright/pytest 配置。
- `README.md`：架构边界、规则模板、运行与扩展说明。
- `src/fin_config_calc/utils/`：无业务含义的底层纯工具与通用文件辅助。
- `src/fin_config_calc/service/contracts.py`：请求、上下文、结果、问题和产物等公共契约。
- `src/fin_config_calc/service/processing.py`：`ProcessingService` 校验与执行门面。
- `src/fin_config_calc/service/config/`：Excel 参数 Schema、Pydantic 规则模型、加载器和校验器。
- `src/fin_config_calc/service/io/`：Excel 源数据读取、报表/快照/审计输出适配器。
- `src/fin_config_calc/service/steps/`：清洗、映射、转换、分摊步骤及注册表。
- `src/fin_config_calc/service/executor.py`：有序步骤执行、进度、取消和异常控制。
- `src/fin_config_calc/service/audit/`：日志、指标、快照与平衡报告。
- `src/fin_config_calc/ui/`：暂时只包含空包标识，为未来 GUI 预留。
- `src/fin_config_calc/cli.py`：`validate`/`run` 最小验收入口。
- `templates/finance_service_template.xlsx`：单工作簿多 Sheet 参数模板。
- `tests/`：单元、集成、架构测试及脱敏 Excel 夹具。

## 验证方式

1. 创建环境并安装依赖后运行 `ruff check .`、`ruff format --check .` 和 `pyright`，确认代码质量、格式和类型检查通过。
2. 运行 `pytest`，重点确认无效参数能在读取业务数据前失败，且错误定位到具体 Sheet/行/规则 ID。
3. 使用示例工作簿运行 CLI 的 `validate`，确认返回零错误并产生独立校验报告；篡改引用和必填列后确认预检能阻止执行。
4. 使用样例数据运行 CLI 的 `run`，核对最终 Excel、步骤日志、中间快照、产物索引均生成，且每一步输入/输出行数可追踪。
5. 对整数、小数、负数、零权重、缺失权重和舍入尾差样本核对分摊平衡，要求分摊前后差异在配置精度内为零，异常进入明细报告。
6. 运行依赖方向检查，确认 `service` 不导入 `ui` 或任何具体 GUI 框架。
7. 手工验收参数模板：财务用户只编辑 Excel 即可完成一个“读取 -> 清洗 -> 映射 -> 分摊 -> 导出”任务，不需修改 Python 代码。

## 已确定事项

- 第 2 层采用单数目录名 `service`，表示向 UI 提供完整的数据加工服务；内部仍按配置、I/O、步骤、执行和审计拆分。
- 保留标准 `src/fin_config_calc` 布局：`src` 隔离源码与测试、模板及项目配置，`fin_config_calc` 是唯一顶级 Python 包名；虽然路径多一层，但能避免从仓库根目录误导入未安装源码，并为测试、打包和未来发布保持一致的导入行为。
- 服务门面命名为 `ProcessingService`，放在 `service/processing.py`，避免 `service/service.py` 的重复命名。
- 首期技术栈为 Python 3.12 + Polars；openpyxl 解析参数工作簿，XlsxWriter 输出结果，Pydantic 承载规则模型。
- 首期数据源与输出仅支持 Excel；CSV、数据库、API 留在 I/O 适配器扩展点，不提前实现。
- 参数采用一个工作簿多 Sheet、线性有序执行；暂不实现 DAG、循环或跨任务依赖。
- 规则是声明式白名单，不支持宏、任意 Excel 公式求值、`eval` 或参数表注入 Python 代码。
- 审计包含运行日志、规则校验报告、可选中间快照和分摊平衡报告。
- `ui` 首轮只保留空包，不定义 UI 接口，也不引入 Tkinter、PySide6 或其他 GUI 依赖；当前通过 CLI 验收 `service`。
- 不在首期加入参数审批、权限、集中服务、多用户并发和参数版本平台；仅记录参数文件摘要以支持本地追溯。
